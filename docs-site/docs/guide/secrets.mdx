Open **Apps** and find **OpenBao** on the Spark. Its name opens the vault's private web interface. Lucia shows whether the vault is running or needs unseal, along with the last successful backup.

## After a restart

**Needs unseal** means the vault's data is still there, but locked. Open the vault and enter the required number of your existing unseal shares. These are the recovery values created when you first initialized OpenBao. Keep them out of chats and screenshots.

Once it is unsealed, you can sign in with the `lucia-oidc` method and the `owners` role. That sign-in exists only after an operator publishes OpenBao's private route. [The deployment guide](../deploy/secrets.mdx) explains the Authentik connection.

## Start and stop

**Start** runs the existing vault with its saved data. **Stop** asks you to confirm because apps using the vault lose access. Stopping does not delete secrets, but starting it afterward requires manual unseal.

Lucia deliberately has no delete or automatic-upgrade button for this vault. An upgrade needs an operator's backup and recovery checks.

If Lucia shows **Container missing**, Start can recreate the container using its saved data. But **Data needs attention** means the service found an empty or wrong data mount. Do not initialize a replacement vault; ask the operator to check the original storage.
