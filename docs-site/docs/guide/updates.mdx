## What the page is for

The Spark runs DGX OS, which is Ubuntu underneath, so it gets package updates like any Ubuntu computer. Most are small. A few replace the kernel, the NVIDIA driver or the container runtime, and those can interrupt Lucia, Local AI or both.

Open **Spark updates** in the sidebar under **Your lab**. The page lists what is waiting, splits it into two groups, and installs it for you now or at a time you pick. You do not need a terminal after the first setup.

Managed servers are separate. They update through **Devices**, or through the assistant. This page is only for the Spark itself. See [Servers](./servers.mdx).

## First time: switch on the update service

Installing software needs administrator rights, and Lucia's web part deliberately has none. So a small helper runs on the Spark with those rights and does only a short list of jobs: check, install the updates you chose, restart services, restart the Spark, and repair.

Until the helper is set up, the page says **Set up Lucia's update service** and shows one command. Open a terminal on the Spark, signed in as yourself, and paste it:

```bash
sudo python3 ~/.local/share/lucia/bootstrap/app/tools/packages/package_worker.py install
```

It asks for your password once. When it prints "Lucia package updates installed", go back to the page. It notices within a few seconds.

If it says `python3-apt is required`, install that package first with `sudo apt install python3-apt`, then run the command again.

## The two groups

| Group | What is in it | What to do |
|---|---|---|
| **Everyday updates** | Ubuntu and application packages | Safe to install while you work. New ones start ticked. |
| **Platform updates** | The kernel, NVIDIA driver, CUDA, DGX software, Docker, boot files and firmware | Install these on their own, ideally after hours. They are never ticked for you. |

Each row shows the package, the version it will move to and where it comes from. Small badges tell you more:

- **Security** means it fixes a known security problem.
- **Needs Spark restart** means it only takes effect after the Spark restarts.
- **Restarts Lucia briefly** means Docker restarts, so Lucia is offline for about a minute.
- **Phased rollout** and **Held back by apt** mean Ubuntu is releasing it slowly or needs extra packages. Installing is still fine.

**Changelog** on any row shows what changed in that version.

## Check for updates

Press **Check for updates** at the top. Lucia asks the Spark to refresh its package lists, then compares what is installed. That can take a minute. Lucia does not do this on a timer, so press it when you want fresh information.

## Install now

1. Tick what you want, or use **Select all** in a group.
2. Press **Install … now**. For platform updates the button reads **Review platform install**.
3. Choose what should happen **Afterwards**:
   - restart the services that use the updated files, and the Spark too if an update needs it;
   - restart only those services;
   - restart nothing, and decide later.
4. Press **Install now** (**Install platform updates** for the platform group).

A progress bar shows the current step and package. You can close the page. The install keeps going, and you can come back to watch it.

For platform updates you also tick **I understand Local AI will be unavailable and the Spark may restart.** That is a real interruption. Lucia unloads your models first, so apps using Local AI get errors until the updates finish. It loads them again when the updates finish, or after the Spark restarts. If something goes wrong, it gives up waiting after three hours rather than leave Local AI off.

Lucia will not install an update that would remove other software. It stops and says which package is in the way.

## Update everything

The **Update everything** card, with its **Update all** button, installs every update in one pass, platform ones included. Lucia restarts the affected services, and then the Spark if something needs it. Use it when you are around and the Spark can be offline for a few minutes.

## Schedule a window

Most people pick the middle of the night. Press **Schedule** on any group, or on **Update everything**, choose a start time and save.

- The time is in your browser's time zone.
- It must be at least two minutes ahead and no more than 30 days.
- You can have one window at a time. Cancel it to plan another.
- If Lucia or the Spark was off, or busy, for more than an hour after the start time, the window is skipped and the page tells you so.
- If you scheduled "everything", Lucia installs whatever is waiting at that moment.

The page shows the result of the last window under **Scheduled window**.

## Restarts

**Needs attention** appears when a restart is waiting. A typical message is "A new kernel is installed but the Spark is still running the old one."

- **Restart now** asks you to confirm, then restarts the Spark.
- **Schedule restart** does the same at a time you choose, and only if it is still needed.
- **Restart services** appears when some programs still use old files. It takes a few seconds and does not restart the Spark.

Some programs can't be restarted while the Spark is running. dbus, systemd-logind and Docker are the usual ones, since everything else leans on them. If they're still listed after **Restart services**, Lucia moves them under **Restart the Spark to finish updating** and asks for a restart.

When nothing is waiting, a **Restart the Spark** section sits at the bottom of the page. Use it when you know a restart is needed and Lucia hasn't asked for one. It asks you to confirm first, like **Restart now**.

:::warning
Restarting the Spark takes Lucia, Local AI and every app on it offline for a few minutes. Your managed servers keep running their apps, but nothing can manage them until the Spark is back. The page reconnects by itself.
:::

## Platform images

Lucia itself runs on a handful of programs it didn't write: Authentik for sign-in, the Traefik gateway every web address goes through, a certificate authority, the OpenLDAP directory, the PostgreSQL database Authentik keeps its data in, and a telemetry relay with two exporters. Each one is a container image that Lucia pins to an exact version. App updates never touch them, so they get their own section, **Platform images**, near the bottom of this page.

Each row shows the service, the version it runs and the rule Lucia follows for it. When the image's registry has something newer that the rule allows, the row lists it with a **Release notes** link right next to its **Update** button. You don't have to read the notes before you update. They're there so you can.

| Rule | Services | What Lucia offers |
|---|---|---|
| Patches only | PostgreSQL, OpenLDAP | Versions where only the last number changes. Databases can need their data moved between bigger versions. |
| Patches, then one release line at a time | Authentik (server and worker together) | Patches first. Then the next release line, say 2026.8 to 2026.10, with an **Upgrade notes** link. Authentik changes its database when it moves line, and it can't skip one. |
| Same major version | Traefik, step-ca, the telemetry relay and exporters | Anything with the same first number. A new major version shows as **Breaking** with **Needs a new Lucia release**, and no button. |
| Shown only | The gateway's CrowdSec plugin | Its newest release, with notes. Its download is pinned by a checksum in Lucia's code, so updating it waits for a Lucia release. |

A version tagged **Rebuild with OS fixes** keeps its number. The project rebuilt the same version with operating system patches underneath, which happens a lot with PostgreSQL and OpenLDAP.

### Update one service, or all the patches

1. Press **Update** next to the version you want, or **Update all patches** at the top of the section for every patch and rebuild at once.
2. Read what restarts. Updating Authentik, the gateway, PostgreSQL or OpenLDAP restarts every web route, so Lucia, sign-in and your apps' web addresses are unreachable for 10 to 15 seconds. The certificate authority and the telemetry services don't touch web traffic.
3. Press **Update now**.

The Spark then checks each image with its registry itself, pulls it, restarts the services that use it and waits up to five minutes for every one to come back. Authentik alone takes about 30 seconds. If anything stays down, the Spark puts the previous images back and says why. For an Authentik release line it also backs up Authentik's database first and restores it if the update fails.

Do patches before minor updates, and move Authentik one release line at a time with a working sign-in in between. Lucia won't combine a release line with any other update.

If Qwen3.8-Flash-Next is running, the confirmation says so. You can still go ahead, but Qwen holds most of the Spark's memory, so pulling images and restarting services takes longer and is more likely to go wrong. Stop it on the AI page first if you can. The Assistant gives the same warning and leaves the choice to you.

### First time: switch on the platform update service

Like package updates, this needs a helper on the Spark, because Lucia's web part has no access to Docker. A fresh install sets it up for you. If the section says the service isn't set up, open a terminal on the Spark, signed in as yourself, and run:

```bash
python3 ~/.local/share/lucia/bootstrap/app/tools/runners/platform_update_worker.py install
```

No `sudo` this time. It runs as you, the same account that set Lucia up.

### The dashboard badge

When a patch for Authentik, the gateway or the certificate authority has waited more than seven days, the **Your Spark** card on the dashboard shows **Security update waiting** with the version and how long. It links here. Lucia never applies these on its own.

## The NVIDIA device list

Containers that use the GPU, such as Qwen3.8-Flash-Next and Lucia's GPU exporter, start from a list of NVIDIA driver files the Spark writes when it boots. When an NVIDIA package update replaces one of those files, the list still names the old one and every GPU container fails to start. A restart fixes it. So does a refresh, which takes seconds.

Lucia refreshes the list itself after it installs NVIDIA or CUDA packages. When something else changed them, say a manual `apt` or Ubuntu's automatic updates, **Needs attention** shows **The NVIDIA device list is out of date** and the first missing file. Press **Refresh NVIDIA device list**. Nothing restarts.

Until the list is current, platform image updates wait and Qwen3.8-Flash-Next won't start; both tell you to refresh first.

## Automatic security updates

Lucia does not switch on automatic updates for you. It reports what it finds: on, or installed but off, or not installed. When they are off, security fixes wait for you on this page.

## When something looks wrong

| You see | What to do |
|---|---|
| **Set up Lucia's update service** | Run the command above once. |
| "Lucia's update service stopped responding" | It restarts on its own. If this lasts, run `sudo systemctl status lucia-package-updates` on the Spark. |
| "An earlier package install was interrupted" or **The package database has unfinished installs** | Press **Repair package database**. It finishes what the earlier install started and installs nothing new. |
| "Another package tool … was busy" | Something else is running apt, often the automatic updater. Wait a few minutes and try again. |
| "ran out of disk space" | Free space on the Spark's system disk, then press **Repair package database**. |
| "could not download" | The Spark cannot reach the package servers. Check its internet connection. |
| **Local AI is paused** stays for a long time | A platform update is probably still running. Check **Update history** at the bottom of the page. |
| A task shows **Interrupted** | The update service restarted during it. Run **Repair package database**, then **Check for updates**. |
| **The NVIDIA device list is out of date** | Press **Refresh NVIDIA device list**. If it still says so, restart the Spark. |
| A platform update says "Another identity deploy or Lucia update is running" | Someone is deploying Lucia or installing packages. Try again in a few minutes. |
| A platform update failed and "put the previous images back" | Everything is as it was. The message says which service didn't come back. Read its release notes before you try again. |
| "The Spark's platform update service stopped responding" | It restarts on its own. If this lasts, run `systemctl --user status lucia-platform-update` on the Spark. |

Failed tasks keep the last lines apt printed, under **Update history**. Copy those when you ask for help.

## Using the assistant

The assistant can look at updates and ask the Spark to check, and it can install them when you say so. Installing always asks you first. It never restarts the Spark on its own. It tells you when a restart is needed and leaves the choice to you. See [Assistant](./assistant.mdx).

It can also list platform image updates, apply them and refresh the NVIDIA device list. Its built-in **platform-image-updates** guide has it do patches first, Authentik one release line at a time, and mention it when Qwen3.8-Flash-Next is running. Applying asks you first and tells you what restarts.
