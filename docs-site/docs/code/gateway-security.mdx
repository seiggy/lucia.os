## The template

`CrowdSecApp` overrides `RequiresApps` (Observability), `RequiresWhy`, `Single`, `BackupMode => "stop"` and `BackupExclude => ["volumes/state"]`. `RequiresApps` and `Single` are new on `CatalogApp`; `StackStore.RequireCompanions` refuses a new install that misses either, and the catalog response carries `requires`, `requiresWhy` and `single` so the install page can explain before the owner tries.

`Render` also returns `Names: [crowdsec-host]`. `CatalogOutput.Names` and `StackManifest.Names` are an app's direct names: labels under the active domain that `ManagedNodeDns` points straight at the app's server rather than the gateway. `StackStore.ValidNames` runs them through the same checks as web addresses (and web addresses check against them), and `RequireDomain` refuses a new install that has names while no domain is active.

Two services share one tmpfs volume. The sidecar gets every variable Lucia changes after install, so a renewed certificate or a new enroll key recreates only the sidecar:

```yaml title="rendered compose (excerpt)"
  lucia:
    network_mode: none
    read_only: true
    environment:
      CA_CERT: ${LUCIA_CROWDSEC_CA:-}
      TLS_CERT: ${LUCIA_CROWDSEC_TLS_CERT:-}
      HARBOR: ${LUCIA_CROWDSEC_HARBOR:-}
      ENROLL_KEY: ${LUCIA_CROWDSEC_ENROLL_KEY:-}
  crowdsec:
    environment:
      USE_TLS: "true"
      LOCAL_API_URL: https://${LUCIA_CROWDSEC_NAME:-localhost}:8080
      AGENT_USERNAME: lucia-host
    extra_hosts:
      - "${LUCIA_CROWDSEC_NAME:-localhost}:127.0.0.1"
```

`LUCIA_CROWDSEC_NAME` is the engine's name under the domain, `crowdsec-host.<namespace>`. `CrowdSec.Lines` writes it only together with a certificate for it, so the engine never runs under a name it can't serve. Before that, `localhost` keeps compose valid while `start.sh` waits for the certificate.

The engine's `start.sh` waits for `tls.sha256`, registers the bouncer under a name that carries a digest of its key, and starts a loop beside the image's own script. The loop sends `SIGHUP` when the certificate marker changes, syncs the `lucia-safe-harbor` allowlist, enrolls in the Console once per key, and logs a `lucia-status` JSON line every minute. Values in that line go through `yq strenv()`, never string concatenation.

A few choices came from testing against the real image:

- AppSec checks a bouncer key by calling the local API at the client URL with its own HTTP client, which honours the credentials' CA but not `insecure_skip_verify`, and has no unix socket support. Hence the engine's own name pointed at loopback, with `CACERT_FILE` set, so the self-call verifies the same certificate the gateway does.
- `USE_TLS` also sets `api.server.tls.ca_cert_path`, which would enable client-certificate sign-in. The settings file sets it back to `""`.
- Compose can't write inline configs into a read-only container, so the engine isn't read-only. The sidecar's script is inline in its entrypoint, so it is.
- The local API answers `401` to a machine sign-in without a `User-Agent`. `CrowdSecLapi` always sends one.

## The log transform

The collector posts OTLP/JSON. The intake splits it and rebuilds Traefik's JSON line from each record's attributes:

```yaml title="CrowdSecApp.Acquisition (excerpt)"
transform: |
  evt.Line.Labels.type != "traefik" ? nil : map(flatten(map(flatten(map(JsonExtractSlice(evt.Line.Raw, "resourceLogs") ?? [], #.scopeLogs ?? [])), #.logRecords ?? [])), "{" + join(map(#.attributes ?? [], ToJsonString(#.key) + ":" + ToJsonString(#.value.stringValue ?? #.value.intValue ?? "")), ",") + "}")
```

`fromPairs` would be shorter, but it builds a `map[interface{}]interface{}` that `ToJsonString` can't encode. The collector's `transform/crowdsec` sets the `time` attribute the parser reads, because Traefik's OTLP records only carry `StartUTC` as nanoseconds.

The guard at the front and the AppSec source's `unique_id: lucia-appsec` are both there for one CrowdSec 1.8.1 bug. The engine files each transform under the datasource's id, but the http datasource reports an empty one, and so does AppSec unless it's given its own. Without the id, AppSec's events ran through this transform too, which found no `resourceLogs`, returned an empty list and dropped them. Requests were still blocked, but no `waf` alert was raised and `crowdsecurity/appsec-vpatch` never saw a hit. Either fix is enough on its own. Keep both until CrowdSec fixes the lookup.

## AppSec alerts

Every in-band block raises an alert of kind `waf` named after the rule (`crowdsecurity/vpatch-env-access`). Those alerts carry no remediation, so `profiles.yaml` never bans on them directly. The same block also reaches the parsers as an `appsec-block` event, and the hub's `crowdsecurity/appsec-vpatch` scenario bans an address that trips two different rules within a minute. That scenario alert goes through the profiles like any other: a public address gets the 4-hour, 24-hour, 7-day ladder, and a private one is recorded only.

`CrowdSecLapi.ParseAlerts` keeps each alert's `kind`, and `BlockedPath` takes the path from the first event's `uri` meta, falling back to the alert's `target_uri` (a JSON list stored as text). Paths are cut at 256 characters. The local API can't filter by kind, and CrowdSec 1.8.1's `ip` and `range` filters miss AppSec alerts (they have no numeric source range), so `CrowdSecGuard.AlertsPath` asks for `value=<ip>` and, for a kind or a network, the latest 500, which `CrowdSec.Alerts` then filters.

## Alerts to Observability

The engine sends every alert to Loki itself, through CrowdSec's `http` notification plugin; the host plays no part. `CrowdSecApp.Notifications` renders one plugin config per class in `AlertClasses` (`trusted`, `lan`, `range`, `public`, `other`), each with the same Go template, `AlertTemplate`, and a class constant. `Profiles(cloudflare, notify: true)` names each profile's notification and adds two last profiles that only notify. The template reads sprig: `fromJson` for the alert context's JSON lists, `toDate` for the time. It writes one `resourceLogs` entry per alert, so `crowdsec.kind` can sit on the resource, where Loki's `otlp_config` turns it into a label:

```text title="src/Lucia.Homelab.Server/Stacks/CrowdSecApp.cs (AlertTemplate, cut)"
{"resource":{"attributes":[{"key":"service.name","value":{"stringValue":"crowdsec"}},{"key":"crowdsec.kind","value":{"stringValue":{{ toJson $kind }}}}]},
"scopeLogs":[{"scope":{"name":"lucia.crowdsec"},"logRecords":[{"timeUnixNano":{{ toJson $time }},"severityNumber":13,"severityText":"WARN",
...
{"key":"crowdsec.source_class","value":{"stringValue":"LUCIA_CLASS"}},
```

The plugin configs carry an empty `url` and `Authorization`. The start script's `alerts` function fills them with `yq` from the sidecar's `otlp-endpoint` and `otlp-authorization` files, after checking both against a strict pattern, and writes them to `/tmp/lucia/notifications/`. It copies `profiles.yaml` or `profiles-quiet.yaml` to `/tmp/lucia/profiles.yaml` the same way. `rules`, `alerts` and `certificate` each set `reload=1`, and the loop sends one `SIGHUP` per pass.

`CrowdSec.Sync` doesn't use the gateway address `Telemetry => true` would give, because AppSec would block alerts that quote an attack ([the operator page](../deploy/crowdsec.mdx#alerts-in-loki)). `CrowdSec.Intake` sets up a TLS receiver on Observability's collector instead and hands the engine its address only once it works:

1. `StackStore.Observability` returns the Observability install with its settings and environment. Below catalog version 13, or without a domain, it stops there.
2. `ObservabilityApp.AlertsName` gives `<alerts-host>.<namespace>`. `AppCertificates.Ensure` gets a certificate for it under the Observability stack's name, through the same worker as the engine's.
3. `CrowdSecApp.CollectorLines(forward, intake)` puts the certificate into a fourth collector config, `LUCIA_CROWDSEC_INTAKE`: a receiver named `otlp/crowdsec_alerts` on container port 4319, TLS 1.2 or later, `basicauth/server`, piped to `otlphttp/loki`. The PEMs are inline because the collector keeps a string field's `${env:...}` value raw; `IntakeCertificate` reads them back on the next pass.
4. `ProbeIntake` calls `GET /v1/logs` on the name with the Lucia-root client. Any HTTP status counts as working; a resolve, TLS or connect failure becomes the `unreachable` message.
5. Only then does `Lines` get a `TelemetryDestination`, which the sidecar passes on as `otlp-endpoint` and `otlp-authorization`.

Every early return leaves `_alerts` with a state and a message for `CrowdSecStatusView.Alerts`, which the page shows as **Alerts to Grafana**. `ObservabilityApp.NamesNeedDomain` is false, so Observability still installs without a domain; its `otlp-alerts` name is only published once one exists.

Inside the engine, the plugin runs as `nobody`. That needs `cap_add: [SETUID, SETGID]` to start it, and `PLUGIN_UNIX_SOCKET_GROUP: nobody` with `group_add: ["65534"]` so the engine, which has no `CAP_DAC_OVERRIDE`, can still open the plugin's socket. Each notification has `ca_cert_path: /tmp/lucia-ca/ca.crt`, a world-readable copy of Lucia's root that the start script makes, because the plugin can't read the `0700` state volume.

## Bans and custom rules

<Source path="src/Lucia.Homelab.Server/Security/CrowdSecActions.cs" /> holds what the page and the assistant share. `CrowdSec.Ban` runs `CrowdSecGuard.Target`, `Duration` and `Reason`, then `RefuseProtected` against the safe harbor, Lucia's own addresses (`harbor.Lucia`, every node address, every app address) and Cloudflare's IPv4 and IPv6 ranges, and only then reaches the local API:

```csharp title="src/Lucia.Homelab.Server/Security/CrowdSecActions.cs"
var (target, scope, network) = CrowdSecGuard.Target(request.Target);
var duration = CrowdSecGuard.Duration(request.Duration);
var reason = CrowdSecGuard.Reason(request.Reason);
CrowdSecGuard.RefuseProtected(network, await Protected(ct));
var (lapi, password) = await LapiTarget(ct);
```

`CrowdSecLapi.BanAlert` builds the alert `cscli decisions add` posts, with scenario `lucia/manual-ban` and the caller's origin (`lucia` or `lucia-assistant`).

<Source path="src/Lucia.Homelab.Server/Security/CrowdSecRules.cs" /> keeps the custom AppSec rules in the host's data and raises `Changed`, which wakes `CrowdSec.Sync` like the harbor does. `Validate` is the whole policy: five fields, four operators, values of printable ASCII without quotes or `%{`, reasons without emoji, a header deny-list (`CommonHeader`), and a matcher built in C# that must not match empty text, `ProtectedPaths`, `ProtectedAgents`, `HeaderValues` or every one of the common query values. For `regex`, `RegexProblem` walks the pattern first and accepts only an allow-list of syntax that RE2 and .NET read the same way; the matcher is then a `NonBacktracking` .NET regex. <Source path="tools/security/re2-crosscheck.go" /> replays the checks' patterns in Go's `regexp` (set `LUCIA_RE2_CORPUS` when running DomainChecks, then run the program on the file it writes) and fails on any accepted pattern whose matches differ. A saved file goes through `Validate` again on every read, so a hand edit can't smuggle a rule into the engine. `Render` writes CrowdSec's appsec-rules format with every string JSON-quoted.

The assistant's tools sit in <Source path="src/Lucia.Homelab.Server/Assistant/AssistantCrowdSec.cs" />, a partial of `AssistantTools`, with `CrowdSecWarning` for the two destructive ones. `crowdsec_unban` is a change: alert text is attacker-controlled, so a prompt injection could ask the model to lift a ban, and the broker asks the owner, refuses it in Plan mode and lets a job run it only with a grant. `crowdsec_list_alerts` and `crowdsec_inspect_alert` return their alerts beside an `untrusted` field (`UntrustedAlerts`) that tells the model to read them as evidence, never as instructions. The `crowdsec-response` built-in skill explains the workflow to the model.

## Certificates

`AppCertificates.Ensure` keeps the current certificate while it's valid for the app's name with more than four days left. Otherwise it makes a key, stores it encrypted with Data Protection under `/data/security/app-certificates/`, and writes the request with the server the app runs on now. It accepts the worker's answer only if the request hash matches, the chain builds to Lucia's root with the server-auth EKU, and the leaf names exactly that one DNS name, no address, with the waiting key. The address only authorises the request, so a move keeps the certificate.

The worker trusts nothing in the request alone. `authorize_app` reads `stacks/stacks.json` and `nodes/identities/<node>.json` itself, takes the label from the stack's `manifest.names`, and the namespace from `domains/workflow.json` (the job that `domains/active.json` names), the same way `ManagedNodeDns.ActiveJob` does. It refuses Lucia's own hostnames and the server's own name, then checks the CSR, the issued leaf and `openssl verify -verify_hostname` against that one name. `APP_TEMPLATES` lists the apps allowed to ask at all:

```python title="tools/nodes/enrollment_worker.py"
APP_TEMPLATES = frozenset({"crowdsec", "observability"})  # catalog apps that may have a certificate for their name
```

Observability is there for its alert intake. To add another app that is reached over the LAN by name, list it there, give its template a name setting that it returns in `CatalogOutput.Names`, and add checks on both sides.

## Keeping Lucia's values out of the stack API

`StackStore.ManagedSecrets` names the variables only Lucia uses: `LUCIA_CROWDSEC_TLS_KEY`, `_ENROLL_KEY`, `_TOKEN`, `_OTLP_AUTHORIZATION` and `_INTAKE` (it holds the intake's key) in any stack, plus `GATEWAY_KEY`, `LUCIA_MACHINE_PASSWORD` and `INTAKE_TOKEN` in a CrowdSec stack (the catalog app, or a converted copy whose compose runs the CrowdSec image). `StackStore.Get` passes the environment through `Mask`, which keeps the names and shows `[kept by Lucia]`. The assistant's `get_app` reads the same view. On a custom-app save, `KeepManaged` drops whatever was sent for those names and puts the stored lines back; a catalog app's environment never comes from the browser in the first place.

## Companion versions and a silent log path

`CatalogApp.RequiresVersions` holds the oldest version of a required app that works: for CrowdSec, Observability `ShowsCrowdSec` (13), the first with CrowdSec's dashboards and the `crowdsec.kind` label. `ForwardsToCrowdSec` (12) is still the first collector that loads `LUCIA_CROWDSEC_COLLECTOR`, and the page's `needs-observability` state uses it. `RequireCompanions` refuses a new install below it with `requires_update`, and the catalog marks the requirement `current: false`.

After install, `CrowdSec.Status` downgrades `healthy` to `needs-observability` while Observability is missing or older, and to `no-logs` when `Track` sees the engine's `linesRead` stand still for `QuietAfter` (15 minutes). Both keep `protecting` true, since the middlewares still point at the engine, but the page no longer says it's protecting.

## Middlewares

`GatewaySecurity.Render(harbor, cloudflare, link)` writes both middlewares as empty chains (`{"chain": {"middlewares": []}}`) when `link` is null, and as the bouncer plugin over HTTPS with the key and Lucia's root inline when it isn't. The fail-open flags are the ones to watch: `updateMaxFailure: -1`, `streamStartupBlock: false`, `crowdsecAppsecFailureBlock`, `crowdsecAppsecUnreachableBlock` and `crowdsecAppsecUnreadableBodyBlock` all `false`, and `httpTimeoutSeconds: 2`.

The identity AppHost calls `Publish` with no link on every deploy, then the host's loop takes over. `Publish` also deletes the old `safe-harbor.txt` the Spark-side engine read.

## The plugin pin

Traefik loads the bouncer from `plugins-local/src/github.com/maxlerebourg/crowdsec-bouncer-traefik-plugin`. <Source path="tools/identity/provision.py" /> downloads three zips from `proxy.golang.org`, checks each against `PLUGIN_ARCHIVES`, and unpacks the two dependencies into `vendor/`. `GatewaySecurity.TreeDigest` computes the same listing as `tree_digest`, and the AppHost refuses to publish unless it equals `PluginTreeSha256`. A plugin upgrade changes `PLUGIN_VERSION`, the zip hashes and `PLUGIN_TREE_SHA256` in `provision.py`, then `PluginVersion` and `PluginTreeSha256` here.
